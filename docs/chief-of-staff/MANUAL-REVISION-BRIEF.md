## A. The law of priority (Omar, 2026-08-22) — must appear in 00 and be echoed by every type manual
North star: a student solves the question bank (MCQ, written, practical) and then excels in their university exam.
Source priority, highest first:
1. Actual exam papers of that university / year / module (EOM, EOY, resit/Baqoon, end-of-rotation), with official keys or model answers.
2. Department files: department books, department question banks / MCQ books, practical atlases, official lecture files.
3. Doctor notes, student notes, academy material — tier ≤5 only, never as the sole source of an answer.
4. Standard textbooks — only where the corpus has no department text, cited as such in field_notes.
Scope = what the module can examine (its papers + its department book chapter). Priority inside a module: (1) concepts/articles that banked questions need → (2) the rest of the examinable chapter → (3) nothing the module never sits. Sequence: articles before questions (the validator refuses a question whose main concept has no covering article).
Answers come only from an official key or the department book (page cited); never reconciled by hand; questionable printed keys recorded as printed. Garbled keys: render-by-eye with method recorded, else unkeyed and not authored. Image-dependent items → required media requests, never prose rewrites.

## C. Staged pipeline (Omar, 2026-08-22) — new section in 00 and the spine of 13-orchestration.md
Content moves through stages; a record is "finished" only when every stage has passed. Stages, each with its gate and its output folder:
S0 Intake — manifest of sources (sha256, textLayer, name-twins `nameTwinOf`/`twinPreferred`, tier, sitting year by exam type, module). Gate: manifest validates; twins resolved; tier ≤5.
S1 Triage — every printed question read; keys recovered; each question assigned the concept it tests; concept keys searched (live + every docs/*-Source-Imports + docs/import-ready) → live / pending / new. Gate: the triage checkpoint table; TRIAGE APPROVED.
S2 Build — concepts (definition, explicit_objective, canonical_key, exam_signal, evidence_gaps) → articles (covering every tested concept) → questions (MCQ / written / practical). Gate: medical:batch, concept-ids, presence; commit body carries gate lines; question-backed records committed separately from chapter coverage.
S3 Tag & place — taxonomy placement (canonical node, subject ∈ the 20, module id with university prefix for non-Kasr, module_subject, microtopic), universities non-empty, years, blueprint weights, difficulty, cognitive fields, exam_weight_by_year. Gate: catalogue check (57ef0d4), placement resolves, no blank required tags.
S4 Relate — typed concept relations with evidence (03), article ↔ concept links both directions (article.related_concepts and concept.article_ids). Gate: relations batch validates; every question's main concept covered by an article in its library_ids.
S5 Evidence — claims, citations, spans from the department book; every article sentence traceable. Gate: medical:citations; atomicClaimIds-missing = 0.
S6 Media — every record that needs an image/diagram/audio carries `media_recommendations` (what, where, why); practical/imaging/OSCE items with no media are marked, never rewritten as prose. Gate: media ledger per module lists every open request.
S7 Completeness & redundancy — fieldsUsed at or above the manual's floor for every type; explanation_<correct> ≥3 sentences (mechanism + takeaway) and each distractor explained; duplicate-key and label-twin scan (medical:duplicate-keys) clean; no two records for one idea; glossary deduped. Gate: medical:audit delta zero; duplicate scan zero; INDEX per import folder with import order, "Update matching items" flags, expected created/updated, assumed-live ids.
S8 Hand-over — full-sequence simulate in the exact import order Omar will click; per-module INDEX; GATES.md; Omar imports; status flipped to Published by a named reviewer/publisher.
A lane may run S2 for a module before S3–S7, but nothing is "done" until S7; the coverage ledger tracks each record's stage.
